# RazorNet 1.1.0

RazorNet is built on SplitsTree, and this release includes the corrections of SplitsTree 6.11.0 that concern the
parts of SplitsTree that RazorNet offers: the methods for comparison (Neighbor Net, Median Joining and
Min Spanning Network), the Characters filter and the program window. The RazorNet, RazorHaploNet and TCS
algorithms and the Shave and Stretch filters are unchanged. Results that change are listed under Changed results.

## New features

- **Remember Settings**: the tab of each method has a button with three dots before the Run button. Remember
  Settings stores the current option values as your own defaults for that method; a step of that kind that you
  add later in the workflow tab, or choose from the list of methods at the top of a tab, starts with them. Use
  Remembered Settings applies them to the current step, Factory Settings sets all options back to the built-in
  defaults, and Forget Remembered Settings discards what was stored. Remembered settings are not applied to the
  steps that the program sets up when a file is opened, an example is loaded or haplotype data are imported.
- **File → Import → Haplotype Data** with the method RazorNet: the network is passed through the Shave filter
  and the result of that is shown, as when an alignment is opened; the exact network is the step before the
  filter in the workflow. The same holds when RazorNet or RazorHaploNet is added in the workflow tab.

## Bug fixes

- **RazorNet**: a line was written to the message window for each restart of the search, a thousand per run
  with the default options. The summary line of each phase still reports the best length.
- **Help → Open User Manual**: the notes of 1.0.0 name this menu item, but it was not shown in the Help menu. It
  is now, and it opens the user manual at https://husonlab.github.io/razor-net.
- **Neighbor Net, inference algorithm ActiveSet (the default)**: the split weights were not those that fit the
  distances best in the least-squares sense, because the computation stopped too early. It now continues until
  the weights are those of the best fit. This takes longer: about 0.1 seconds rather than 0.03 for 100 taxa, and
  one second rather than 0.2 for 200 taxa.
- **Neighbor Net, distances that are small or large**: a split was discarded if its weight was at most 0.0001
  (0.000001 with the inference algorithm SplitsTree4), whatever the scale of the distances, so that for
  distances of the order of 0.001 most splits were lost and the fit was poor. The value is now relative to the
  largest distance.
- **Neighbor Net, distances that are not numbers**: if a distance was infinite, the computation did not
  terminate with the inference algorithm ActiveSet; if a distance was undefined (NaN), a network with a fit of
  zero was shown without any message. The method now reports the two taxa concerned.
- **Neighbor Net, inference algorithms GradientProjection and APGD**: these two choices have been removed. They
  compute the same split weights as ActiveSet, but more slowly, and as they stopped early their results were the
  least accurate. A file that names one of them is opened with ActiveSet, and a warning is written. The
  inference algorithm SplitsTree4 no longer writes a line of debugging output for every run.
- **Neighbor Net, circular ordering BryantHuson2023**: this ordering, which can be selected in a workflow file
  but is not the default, did not always give an ordering compatible with a circular distance matrix.
- **Median Joining**: in all distances between sequences the first variable site pattern was counted twice, so
  that for some data other median vectors were added than should have been. A median vector was removed when it
  had two links or fewer; for some data the same vectors were then added and removed again without end, and the
  computation did not terminate. A median vector is now removed only when it has fewer than two links, as in
  PopART; one that is left with two links is not drawn as a node, its two edges are shown as one edge with the
  changes of both. The method failed when all sequences are identical.
- **Min Spanning Network**: the network contained edges that do not lie in any minimum spanning tree. All pairs
  of taxa at a given distance were connected, also pairs that were already connected by a path of shorter edges.
  Now two taxa are connected only if no such path exists, so that with Epsilon set to zero the network is the
  union of all minimum spanning trees. The tooltip of Epsilon described another method.
- **Characters filter** (Data → Filter Characters): Exclude Gap Sites had an effect only if Exclude Constant
  Sites or Exclude Parsimony Uninformative Sites was set as well. Sites with three or more states of which at
  most one occurs in two or more sequences were not recognized as parsimony uninformative. A gap or a missing
  state was counted as a state, so that a site that is constant except for a gap was not excluded as constant.
- **Hamming distance**, which the haplotype import uses for a Min Spanning Network: the message that reports
  saturated or missing distances counted each pair of sequences twice.
- **Warnings**: warnings that arise while a file is read or a SplitsTree method runs, for example for a distance
  matrix that is not symmetric or a repeated taxon name in a FASTA file, are shown as notifications in the window
  concerned, as well as in the message window; the same warning is shown at most once a minute.
- **Options with a value that is not known**: when a workflow file names a value for an option that the program
  does not have, the default is used, as before, and a warning is now written.
- **Export**: after an export as Nexus with a taxa block, later exports as Nexus contained a taxa block as well.
- **Alignment view**: the menu items View → Zoom Out and Zoom Out Horizontal did nothing.
- **Menus**: items that cannot do anything in the current tab, such as Edit → Cut for a network, or Copy in the
  workflow tab, are no longer offered.
- **Select → From Previous Window** in a text tab failed when the text selected before contained characters such
  as brackets.

## Changed results

Results obtained with the default options:

- **Neighbor Net**: networks change for most data, as the split weights are now those of the best fit: splits
  appear, others disappear and weights change. For distances that fit a tree or a circular split network exactly,
  nothing changes. For data whose largest distance is less than one, splits of small weight that were discarded
  are now shown; for data whose largest distance is greater than one, splits whose weight is at most 0.0001 times
  that distance are no longer shown.
- **Min Spanning Network**: networks have fewer edges; on simulated haplotype data, about half as many.
- **Median Joining**: networks can change; data for which the computation did not end now give a network.
- **File → Import → Haplotype Data with the method RazorNet**: the network shown is the one simplified by the
  Shave filter.

Results obtained with options set:

- **Characters filter with Exclude Gap Sites, Exclude Constant Sites or Exclude Parsimony Uninformative Sites**:
  more sites are excluded, and the networks computed from the filtered alignment can change.
- **Neighbor Net with the circular ordering BryantHuson2023**: the ordering, and with it the network, can change.
- **Neighbor Net with the inference algorithm GradientProjection or APGD**: computed with ActiveSet.
